# ナレッジの見方と状態の確認

普段は、セットアップで選んだ**個人ナレッジ保存先の `knowledge/index.md`**を開いてください。
公開エンジンのリポジトリやインストール済みSkillは、あなたの記憶の保存先ではありません。

## どこに何があるか

| 場所 | 内容 | 普段見る必要 |
|---|---|---|
| 公開エンジン | 記録・整理・取得を行うプログラム、共通ポリシー、配布用Skill | プログラムの更新時 |
| 個人保存先の `events/` | 追記型の原本。判断・観察・状態変更の記録 | 詳細調査時。削除しない |
| `knowledge/index.md` | 内容の一覧と、個別ファイルへのリンク | 最初に開く入口 |
| `knowledge/observations/` | 作業から残した観察・教訓 | 記録内容を確認するとき |
| `knowledge/candidates/` | 再利用の候補。詳細に有効化条件の不足理由がある | 候補の状態を確認するとき |
| `knowledge/patterns/` | 有効化された再利用知識 | AIが何を再利用できるか確認するとき |
| `knowledge/archive/` | 廃止・置換済みなどの知識 | 過去の判断を確認するとき |
| `knowledge/rules/always-on.md` | 有効知識の中から文字数上限内で選ばれた常時参照用の抜粋 | 必要な場合のみ |
| machine-local runtime | 処理待ちキュー、実行記録、再試行情報、キャッシュ | 不具合調査時 |
| インストール済みSkill | エンジンを呼び出すための配布済みファイル | 通常は直接編集しない |

`knowledge/memories/`は観察記録、`knowledge/library/`は候補・有効知識、`knowledge/rules/`は有効知識の互換配置です。
同じ内容が複数のフォルダにあっても、独立した記憶が複数あるわけではありません。既存の取得処理が使うため、重複に見えても手動で削除しないでください。
空の初期フォルダがあっても、それだけでは記録の欠落を意味しません。

チーム保存先は任意です。無効の場合は未使用で、個人の記録・取得に必須ではありません。
ホスト製品自身が持つメモリも、このエンジンの保存先とは別です。

## 記録されたことと、再利用できることは別

流れは「観察を記録 → 整理 → 候補の条件を確認 → 有効化 → 適用対象に合う知識を取得」です。

- 観察記録: 作業で得た材料。すべてが再利用ルールになるわけではありません。
- 候補: 再利用できる可能性がある知識。通常の取得対象にはまだ含まれません。
- 条件成立・整理処理待ち: 根拠の条件は成立していますが、有効化済みの記録はまだありません。
- 有効化済み: 状態変更の原本と生成結果が存在します。取得時には対象CLI・案件・分野などでさらに絞り込みます。

候補の詳細では、独立した根拠、異なる適用範囲での確認、効果、矛盾、必要項目の不足を説明します。
有効化済みが0件でも、条件を満たす材料がなければ正常です。候補の件数を増やすために条件を緩和することはありません。
根拠を復元できない候補は「未検証」と表示し、推測で根拠を補いません。

## 状態表示の読み方

`status`は診断です。記録を整理・修復したり、同期を実行したりするコマンドではありません。
Skillの`status=success`はJSONを返せたという意味です。健康状態は`health_status`と各項目を確認してください。

| 表示 | 意味 |
|---|---|
| Hook `VERIFIED` | 対象CLIの実動作記録とHook構成を確認できた |
| Hook `UNVERIFIED` | 設置済みでも実動作の証拠が不足。別CLIの成功は流用しない |
| Skill `AVAILABLE` | 配布済みファイル全体とbindingの診断が一致した |
| queue `READY` | 検査済みで問題・処理待ちなし。フォルダがあるだけではこの表示にしない |
| queue `PENDING` / `PROCESSING` | 処理待ち / 処理中 |
| queue `DEFERRED` | 後で再試行する処理が残っている |
| `NEEDS_ATTENTION` | 不正データや期限切れの処理権限など、確認が必要 |
| projection `CURRENT` | 検査した原本スナップショットと索引が一致 |
| projection `STALE` | 原本が更新されており、索引の再生成が必要 |
| projection `UNKNOWN` | 旧形式などで更新確認情報がない。破損と同義ではない |
| maintenance `DISABLED` | 自動整理の定期実行が無効 |
| maintenance `CONFIGURED` | 自動実行設定を確認できた。継続稼働そのものの証明ではない |

`index.md`に書かれた件数は**生成時点**の値です。最新の状態は診断で確認してください。
診断には原本の観察件数と索引の観察件数を別々に表示します。情報分類による除外もあるため、件数差をすべて欠損とは扱いません。
手動整理が成功しても、無効な自動実行設定が有効になったことにはなりません。

## 更新・復旧するとき

AIに頼む場合は「設定済みの個人保存先を維持し、statusとdoctorで索引の鮮度を確認して」と伝えてください。
Skillを呼び出す場合は、セットアップが生成したlauncherコマンドにモードを追加します。`scripts/*.py`を直接実行したり、今作業中の案件をエンジン保存先として指定したりしないでください。

1. 現在の保存先、既存イベントのhash、設定を確認する。実際の値は公開エンジンへ書かない。
2. プログラム更新は既存選択を保持する`update`で行う。更新だけで整理済みとは判断しない。
3. 原本から閲覧・取得用ファイルを作り直すだけなら、設定済みのrootを指定したエンジンCLIの`project`を使う。AI整理や新しい有効化判断は行わない。
4. 取り込み・候補整理・有効化判定まで必要なら`maintain`を使う。整理担当AIへの呼び出しを伴う場合があるため、実行範囲を区別する。
5. 原本が保持されたこと、索引が`CURRENT`になったこと、キュー状態、必要なCLIの実動作記録をそれぞれ確認する。

生成されたMarkdownの直接編集は、次の再生成で失われます。原本修正の代わりにはしないでください。
キューを削除して正常件数を作る、全候補を強制有効化する、無効な定期実行を勝手に再登録する操作は行いません。
